# 约稿费用验收POC工作流 - 重构版技术架构设计

**版本:** v1.0
**日期:** 2026-08-20
**适用范围:** 约稿费用验收POC场景
**技术栈:** Python 3.14 + LangChain + LangGraph + FastAPI + MCP

---

## 1. 文档目的

本文档基于原始业务流程（流程/1.md和2.md），重新设计一个**简化、实用、可扩展**的工作流架构。

### 1.1 核心设计原则

1. **简单优先**: 使用成熟框架，避免过度自研
2. **业务对齐**: 7个节点直接对应真实业务步骤
3. **按需加载**: 表格数据按需读取，减少内存占用
4. **确定性优先**: 核心计算用代码，LLM仅辅助内容理解
5. **错误容忍**: 单条数据错误不中断流程，收集所有问题统一报告
6. **可观测性**: 结构化日志，实时查询节点状态
7. **预留扩展**: 接口设计考虑未来平台集成需求

### 1.2 与原架构的主要差异

| 维度       | 原架构           | 新架构                    |
| ---------- | ---------------- | ------------------------- |
| 节点数量   | 18个技术节点     | 7个业务节点 + 1个输入节点 |
| 数据加载   | 一次性加载所有表 | 按需加载                  |
| 状态管理   | 自研复杂状态系统 | LangGraph内置Checkpointer |
| 错误处理   | 严格中断         | 收集错误继续执行          |
| MCP接口    | 未明确           | FastAPI + MCP工具包装     |
| 代码复杂度 | 高度抽象         | 直接实现业务逻辑          |

## 2. 业务流程与节点设计

### 2.1 7个业务节点定义

```
节点0: 输入节点 - 接收表1，验证其他表的可用性
节点1: 填写约稿资料基础信息 - 解析表1，填充媒体名称、链接、平台
节点2: 完善发布信息 - 补充发布形式、约稿类型、标题、截图、日期、数量
节点3: 匹配媒体库 - 根据表3补充媒体级别、粉丝量
节点4: 匹配账户信息 - 根据表4补充户名、身份证、账号等
节点5: 匹配费用并计算 - 根据表5匹配费用，计算金额，生成约稿明细
节点6: 汇总并生成付款表 - 月度汇总，生成约稿费用合计和付款表
```

### 2.2 节点输入输出设计

#### 通用输出结构

```python
{
    "status": "success" | "partial_success" | "failed",
    "processed_count": int,  # 处理的记录数
    "success_count": int,    # 成功的记录数
    "data": dict | list,     # 处理后的数据
    "issues": [              # 收集的问题列表

            "level": "warning" | "error",
            "code": str,
            "message": str,
            "record_id": str,
            "field": str
        }
    ],
    "metrics": {             # 统计指标
        "duration_ms": float,
        "memory_mb": float
    }
}
```

#### 节点0: 输入节点

**输入:**

- 用户上传的 `1-链接.xlsx`
- 配置的表格目录路径

**处理:**

1. 验证表1文件存在且可读
2. 扫描表格目录，检查表2-6是否存在
3. 记录所有表格的元信息（文件大小、修改时间、Sheet名称）
4. 生成文件路径映射

**输出:**

```python
{
    "status": "success",
    "table_paths": {
        "1-链接": "/path/to/1-链接.xlsx",
        "2-约稿资料": "/path/to/2-约稿资料.xlsx",
        "3-媒体库": "/path/to/3-媒体库.xlsx",
        "4-账户信息": "/path/to/4-账户信息.xlsx",
        "5-费用": "/path/to/5-费用.xlsx",
        "6-付款": "/path/to/6-付款.xlsx"
    },
    "table_metadata": {
        "1-链接": {
            "size_bytes": 12345,
            "sheet_names": ["Sheet1"],
            "row_count": 44,
            "col_count": 2
        },
        # ... 其他表的元信息
    },
    "issues": []
}
```

**失败条件:**

- 表1不存在或损坏
- 表3、4、5任一缺失（这些是必需的参考表）

## 4. 核心实现要点

### 4.1 LangGraph状态定义

```python
from typing import TypedDict, List, Dict, Any, Optional

class WorkflowState(TypedDict):
    """工作流状态，在节点间传递"""
  
    # 运行元信息
    run_id: str
    run_started_at: str
  
    # 表格路径（节点0输出）
    table_paths: Dict[str, str]
    table_metadata: Dict[str, Dict[str, Any]]
  
    # 各节点处理后的数据
    records: List[Dict[str, Any]]  # 逐步丰富的记录列表
  
    # 计算结果
    quote_details: Optional[List[Dict[str, Any]]]
    monthly_summary: Optional[List[Dict[str, Any]]]
    payment_rows: Optional[List[Dict[str, Any]]]
  
    # 输出文件路径
    output_files: Dict[str, str]
  
    # 问题收集（跨节点累积）
    issues: List[Dict[str, Any]]
  
    # 节点状态追踪
    node_statuses: Dict[str, Dict[str, Any]]
  
    # 统计指标
    metrics: Dict[str, Any]
```

### 4.2 节点基类设计

```python
from abc import ABC, abstractmethod
from typing import Dict, Any
import time
import structlog

logger = structlog.get_logger()

class BaseNode(ABC):
    """节点基类，统一处理日志、错误收集、状态更新"""
  
    def __init__(self, node_id: str, node_name: str):
        self.node_id = node_id
        self.node_name = node_name
  
    def __call__(self, state: Dict[str, Any]) -> Dict[str, Any]:
        """节点执行入口，包装了日志和错误处理"""
        start_time = time.time()
    
        logger.info(
            "node_started",
            node_id=self.node_id,
            node_name=self.node_name,
            run_id=state.get("run_id")
        )
    
        try:
            # 更新节点状态为running
            self._update_node_status(state, "running")
        
            # 执行节点逻辑
            result = self.execute(state)
        
            # 计算耗时
            duration_ms = (time.time() - start_time) * 1000
        
            # 更新节点状态为completed
            self._update_node_status(
                state, 
                "completed",
                metrics={"duration_ms": duration_ms}
            )
        
            logger.info(
                "node_completed",
                node_id=self.node_id,
                duration_ms=duration_ms,
                status=result.get("status")
            )
        
            return result
        
        except Exception as e:
            duration_ms = (time.time() - start_time) * 1000
        
            logger.error(
                "node_failed",
                node_id=self.node_id,
                error=str(e),
                duration_ms=duration_ms
            )
        
            # 更新节点状态为failed
            self._update_node_status(state, "failed", error=str(e))
        
            # 返回失败结果但不中断流程
            return {
                "status": "failed",
                "error": str(e),
                "issues": [{
                    "level": "error",
                    "code": "NODE_EXECUTION_FAILED",
                    "message": str(e),
                    "node_id": self.node_id
                }]
            }
  
    @abstractmethod
    def execute(self, state: Dict[str, Any]) -> Dict[str, Any]:
        """子类实现具体的节点逻辑"""
        pass
  
    def _update_node_status(
        self, 
        state: Dict[str, Any], 
        status: str,
        metrics: Dict[str, Any] = None,
        error: str = None
    ):
        """更新节点状态"""
        if "node_statuses" not in state:
            state["node_statuses"] = {}
    
        state["node_statuses"][self.node_id] = {
            "status": status,
            "metrics": metrics or {},
            "error": error
        }
```

### 4.3 Excel读取服务

```python
from openpyxl import load_workbook
from typing import List, Dict, Any
import structlog

logger = structlog.get_logger()

class ExcelService:
    """Excel读写服务"""
  
    @staticmethod
    def read_sheet_as_dicts(
        file_path: str, 
        sheet_name: str = None,
        skip_rows: int = 0
    ) -> List[Dict[str, Any]]:
        """
        读取Excel sheet并转换为字典列表
    
        Args:
            file_path: Excel文件路径
            sheet_name: Sheet名称，None表示第一个sheet
            skip_rows: 跳过的行数
        
        Returns:
            字典列表，每个字典代表一行
        """
        wb = load_workbook(file_path, data_only=True)
        ws = wb[sheet_name] if sheet_name else wb.active
    
        # 获取表头
        headers = []
        for cell in ws[skip_rows + 1]:
            headers.append(cell.value)
    
        # 读取数据
        rows = []
        for row in ws.iter_rows(min_row=skip_rows + 2, values_only=True):
            row_dict = {}
            for header, value in zip(headers, row):
                row_dict[header] = value
            rows.append(row_dict)
    
        wb.close()
    
        logger.info(
            "excel_read",
            file_path=file_path,
            sheet_name=sheet_name or ws.title,
            rows_read=len(rows)
        )
    
        return rows
  
    @staticmethod
    def get_metadata(file_path: str) -> Dict[str, Any]:
        """获取Excel文件元信息"""
        import os
    
        wb = load_workbook(file_path, data_only=True)
    
        metadata = {
            "size_bytes": os.path.getsize(file_path),
            "sheet_names": wb.sheetnames,
            "sheets": {}
        }
    
        for sheet_name in wb.sheetnames:
            ws = wb[sheet_name]
            metadata["sheets"][sheet_name] = {
                "max_row": ws.max_row,
                "max_column": ws.max_column
            }
    
        wb.close()
        return metadata
```

```python
from typing import List, Dict, Any, Literal

class IssueCollector:
    """统一的错误收集器"""
  
    def __init__(self):
        self.issues: List[Dict[str, Any]] = []
  
    def add_issue(
        self,
        level: Literal["warning", "error"],
        code: str,
        message: str,
        record_id: str = None,
        field: str = None,
        **kwargs
    ):
        """添加一个问题"""
        issue = {
            "level": level,
            "code": code,
            "message": message,
        }
    
        if record_id:
            issue["record_id"] = record_id
        if field:
            issue["field"] = field
    
        # 添加额外信息
        issue.update(kwargs)
    
        self.issues.append(issue)
  
    def get_issues(self) -> List[Dict[str, Any]]:
        """获取所有问题"""
        return self.issues
  
    def has_errors(self) -> bool:
        """是否有error级别的问题"""
        return any(issue["level"] == "error" for issue in self.issues)
  
    def get_summary(self) -> Dict[str, int]:
        """获取问题汇总"""
        return {
            "total": len(self.issues),
            "warnings": sum(1 for i in self.issues if i["level"] == "warning"),
            "errors": sum(1 for i in self.issues if i["level"] == "error")
        }
```

```python
    graph.add_node("node_05", Node05CalculateFee("node_05", "计算费用"))
    graph.add_node("node_06", Node06GeneratePayment("node_06", "生成付款表"))

    graph.add_edge("node_01", "node_02")
    graph.add_edge("node_02", "node_03")
    graph.add_edge("node_03", "node_04")
    graph.add_edge("node_04", "node_05")
    graph.add_edge("node_05", "node_06")
    graph.add_edge("node_06", END)
  
    # 编译图
    return graph.compile(checkpointer=checkpointer)
```

```python
from pathlib import Path
from typing import Dict, Any

class Config:
    """配置管理器"""
```

## 9. 关键差异点说明

### 9.1 为什么选择粗粒度节点？

**原因:**

1. 业务对齐：每个节点对应一个完整的业务步骤
2. 易于理解：非技术人员也能看懂工作流
3. 减少通信开销：节点间传递的数据更少
4. 方便扩展：未来可以在节点内部拆分子步骤

### 9.2 为什么按需读取表格？

**原因:**

1. 内存效率：不需要一次性加载所有表格到内存
2. 灵活性：不同节点可以用不同方式读取同一个表
3. 可扩展：未来表格变大时不需要重构架构

### 9.3 为什么使用结构化字典输出？

**原因:**

1. 灵活性：比Pydantic模型更灵活，POC阶段快速迭代
2. 可序列化：LangGraph状态需要序列化到检查点
3. 易于调试：可以直接打印和查看
4. 渐进式：未来可以逐步添加Pydantic验证

### 9.4 为什么收集错误而不中断？

**原因:**

1. 批处理特性：处理多条记录，一条失败不应影响其他
2. 人工复核：收集所有问题后统一处理更高效
3. 成本考虑：避免重复运行整个流程
